# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What Verbo is

Verbo is a web-based Chinese-language learning platform. It combines live tutor booking, a structured study plan, podcasts with transcripts, OCR-based text scanning (photo/upload Chinese text → Pinyin + English translation), and spaced-repetition flashcards. Every word encountered in any module (Scan, Practice, Podcast, Study) auto-saves to one shared personal flashcard bank — this cross-module flashcard sync is the core product idea tying the modules together.

Planned modules: Scan (OCR), Practice, Find Tutor, Podcast, Study, Flashcard Bank.

Hover-then-shortcut is the established save pattern for read-only word displays (Read, and any future module that renders tokenized text): hovering a word shows a pinyin/translation tooltip, and pressing **Alt+1** while hovering saves it to the flashcard bank — there is no click-to-save. That tooltip is the shared `components/WordPopover.jsx` (prefix `wp-`) — a styled `position: fixed` card that clamps to the viewport edges and flips below the word when there is no room above — used by `ScanDocument`, `ReadArticle` and `PodcastEpisode`. Each of those pairs it with a token class (`sd-token` / `rd-word` / `pe-word`) whose `.active` state mirrors `:hover`, so the highlight and the popover are driven by one piece of state and cannot disagree. **`StudyUnit` currently has no hover-translate at all**: `hoveredWordRef` is still declared and read by its Alt+1 listener but nothing ever assigns to it, because the Reading rework replaced the annotated `reading_tokens` render with plain per-character spans over `study_text_lines`. Restoring it needs the backend to annotate each line's `chinese` the way `ArticleController::show` does. The popover's saved state is scoped to the current page view, so its footer says "Saved", never "in your flashcards" — nothing on the page knows what the bank already contains. `ReadArticle.jsx` tracks the hovered token in a ref (`hoveredWordRef`, updated on `onMouseEnter`/`onMouseLeave`) read by a single `keydown` listener, avoiding stale-closure issues without re-subscribing the listener per hover.

## Architecture

Two-app monorepo, functionality-first (no visual design/styling applied yet — plain unstyled HTML elements throughout):

- `frontend/` — React (Vite), React Router for pages, plain `fetch`-based API client (`src/api.js`), auth state in `src/context/AuthContext.jsx` (token kept in `localStorage`)
- `backend/` — Laravel 9 API, Sanctum token auth (not SPA cookie auth — the frontend sends `Authorization: Bearer <token>`), SQLite for local dev (`database/database.sqlite`)

**Working features: Auth, Flashcard Bank, Scan (OCR), Read, Find Tutor, Podcast, Study, Dashboard.** This is the pattern to replicate for the last remaining module (Practice):
- Backend: `routes/api.php` → `Api\AuthController` (register/login/logout/me), `Api\FlashcardController` (index/store/destroy), `Api\ScanController` (index/store/show), `Api\ArticleController` (index/show/store/update/destroy), `Api\TutorController` (index/show/store), `Api\BookingController` (index/store), `Api\PodcastController` (index/show/store/update/destroy), `Api\StudyLevelController`/`Api\StudyUnitController`/`Api\StudyVocabularyController`, `Api\QuoteController` (show/store), all under `App\Http\Controllers\Api`. Flashcards belong to a user via `User::flashcards()` / `Flashcard::user()`; ownership checks must cast IDs (`(int) $model->user_id !== $request->user()->id`) since SQLite returns foreign keys as strings — a bare `!==` silently 403s the rightful owner.
- Every scan is persisted (`scans` table: `user_id`, `original_filename`, `raw_text`, `words` json, `size_bytes`) — `size_bytes` must be read off the `UploadedFile` *before* the OCR block, since the `finally` deletes the upload and the size can never be recovered afterwards; it is nullable, and scans predating it render an em dash in the Documents table — Scan is a saved-document history, not a one-shot ephemeral result. `ScanController::index` returns lightweight list rows, `show` returns the full record (same shape `store` returns). The upload area is a drop zone with a queue: photos arrive by browse, drag-and-drop or **Ctrl+V paste**, all three funnelling through one `addFiles()` so the size limit and its wording cannot drift between them. Scanning runs the queue **sequentially** (OCR is CPU-bound and the endpoint shares the 300/min bucket); one photo navigates to its document page, several stay put against a refreshed list. Progress uses `api.scanWithProgress`, an XHR upload — `fetch()` cannot report upload progress — and the row flips to an indeterminate sweep once the bytes are sent, because OCR time is not measurable from the client and a bar sitting at 100% would be a lie. **Results always render on their own page** — `ScanDocument.jsx` at `/scan/:id` — never inline on the index: clicking a row in the Documents table links there, and a finished upload navigates there too, so a fresh scan and a reopened one are the same screen rather than two divergent UIs. `ScanController::show` and `destroy` are ownership-gated with the usual `(int)` cast, so a scan is only viewable and deletable by the account that made it. Delete needs no file cleanup — `store` already removes the upload once OCR finishes, so the row is all that persists. Both delete entry points (the hero button on `ScanDocument`, the row's ⋮ menu on the index) arm on the first click and act on the second; the page-level one disarms after 4s on a timer rather than on blur, since blur never fires if focus never landed on the button. `show` also runs `DictionaryService::annotate()` on `raw_text` (same as Read/Podcast/Study) and returns `tokens`, so the scanned text gets the identical hover + Alt+1 save treatment — `saved` is keyed by the word string and shared with the aside's Save buttons, so a hover-save also flips the matching list row. **Scans can be shared by public link** (`scans.share_token`, nullable + unique; null means private): the row's ⋮ menu offers Open / Share / Delete, and Share opens a dialog with the link, Copy, and Stop sharing. `POST /scans/{scan}/share` is **idempotent** — it returns the existing token rather than rotating it, so a link already sent out does not silently die when the owner reopens the dialog — and `DELETE /scans/{scan}/share` revokes, which breaks every copy of the link instantly. `GET /shared/scans/{token}` is the one Scan route **outside** `auth:sanctum`: the token is the credential, so it is 40 chars from `Str::random`. That response is hand-built rather than `$scan->toArray()` because it goes to anyone on the internet — it must never carry `user_id`, the token, or the row id; only filename, text, words, created_at and the annotated tokens. The recipient's page is `pages/SharedScan.jsx` (prefix `ss-`) at `/shared/scan/:shareToken`, mounted outside both `ProtectedRoute` and `Layout` since the visitor has no account and there is no sidebar to render; hover-translation works there but **Alt+1 saving does not**, because saving needs a flashcard bank to save into. The Documents table's "Shared Users" column is no longer `N/A` — it reads Private / Anyone with link off `share_token`. The page splits text left / word list right (sticky aside), mirroring `StudyUnit`'s reading layout since the content has the same shape; "Save all" iterates sequentially rather than `Promise.all` because the flashcard endpoint shares the 300/min bucket.
- Frontend: `src/pages/{Register,Login,Dashboard,Flashcards,Scan,ScanDocument,Read,ReadArticle,FindTutor,Podcast,PodcastEpisode,Study,StudyLevel,StudyUnit}.jsx`, `src/components/{ProtectedRoute,Layout}.jsx` — `Layout` renders the sidebar (all 8 nav items, Dashboard first) and gates the authenticated area via nested routes in `App.jsx`; `AuthProvider` wraps the app in `main.jsx`. `/` redirects to `/dashboard` (the landing page after login), not `/flashcards`.
- **Dashboard is a read-mostly aggregator, not its own data domain**: it pulls from `GET /tutors` (Recommend Teachers, first 3), `GET /articles` (Top Reads), `GET /podcasts` (Pick up + the Podcasts row) and `GET /study-levels` (the study tile in Pick up) — no new endpoints, just client-side `.slice()` on existing lists. The one piece of its own data is `quotes` (a table with a single row, id 1) — `QuoteController::store` always upserts that one row rather than creating per-user quotes, since the quote is global and admin-edited, shown to every user via `GET /quote`.
- **Layout is measured off `design/dashboard/Dashboard.jpg`** (the newer export — `design/Dashboard.jpg` is an earlier, simpler version, superseded). Full-width hero, then a two-column body: a left content panel and a right rail, `749fr / 420fr` with a 26px gutter, held as `fr` so the 1.78:1 split survives any width instead of only matching at the export's size. Both panels are white with a 1px `#c8c8c8` outline; inner cards use the 1px `#2b2644` navy the rest of the app uses. Sampled colours: hero/duration-badge/peak-bar `#7d76a0`, "Unit" tag `#bcb3e8`, level tag `#fe916a`, activity bar `#d5c6ff`, "View all" pill `#a89ce3`, section bar `#8d87ad`, cover placeholder `#cccbd1`, page `#f9f8fe`. The Pick-up row (`.db-pickup`) **fits the panel rather than scrolling** — the design runs it off the edge, but a visible scrollbar there was unwanted, so the three tiles hold the export's 327 : 209 : 209 proportions as flex weights against a `0` basis and share whatever width there is. `min-width` floors (260 / 175) make the row wrap on a narrow panel instead of crushing the tiles, so it is capped at the study tile plus two podcasts. Don't reintroduce `overflow-x: auto` here: it forces `overflow-y` to compute to `auto` too, which clips the cards' hover lift and shadow.
- **Large parts of the Dashboard design have no backend and are explicit placeholders**, grouped as `PLACEHOLDER_*` constants at the top of `Dashboard.jsx` so it is obvious what is real: podcasts have no duration or author column (`8mins` / `Chen Mingyue` / language line), tutors have no lesson count or rating (`275 Lesson` / `4.9 Rating`), there is no enrolment or schedule table at all (**My Course**), and until recently nothing recorded time spent — **Stats Summary is real now**: `activity_days` (`user_id`, `day` as a plain Y-m-d string, `seconds`, `last_beat_at`, unique on user+day) is fed by `POST /activity/heartbeat`, which `hooks/useActivityHeartbeat.js` calls once a minute from `Layout` (so every authenticated page is covered). The beat **carries no duration**: `ActivityController::heartbeat` credits the gap between beats measured server-side and clamps it to 120s, so a client cannot inflate the one number on this page a user might want to game, and time asleep/hidden is dropped rather than back-filled. The client only beats while the tab is visible AND there has been input in the last 5 minutes, so a page left open overnight does not count. `GET /activity/summary?days=N` (N clamped 1..31) returns one bucket per day including empty ones, so the chart always has seven bars. **`ActivityDay.day` must NOT be cast to `date`** — the cast writes back `Y-m-d 00:00:00`, so a `firstOrCreate` keyed on `Y-m-d` never matches and inserts a duplicate on every beat. The unrelated `GET /activity` (a recent-activity feed derived from flashcards/scans/bookings) still exists but no page uses it. **The streak badge is real too** — derived from `activity_days`, not a new table: `ActivityController::streaks()` walks the descending day list and rides along in the `/activity/summary` response, so the badge costs no extra request. A day counts if it has a row **at all**, not if it clears a minimum — the first heartbeat of a day credits 0 seconds by design, so a threshold would deny credit to someone who genuinely turned up briefly. The run may end **today or yesterday**, so the badge does not read 0 all morning before the user opens the app; it only breaks once a full day is missed. The query is capped at 400 rows since nothing older can affect a current streak. Reads "N day streak" — attributive, never "N days streak" — and drops to a greyed "No streak yet" when the run is broken. And **"Pick up where you left off" IS real resume state** — `study_progress` (`user_id`, `study_unit_id`, `last_viewed_at`, unique on the pair, indexed on `user_id + last_viewed_at`) records every unit a user opens. `StudyUnit.jsx` pings `POST /study-units/{unit}/view` on load, fire-and-forget so a failure never blocks the page; `GET /study-progress/latest` returns the newest one shaped for the tile (unit + level + a 1-based `position` so it can say "Unit N"). It answers **204, not 404**, when the user has never opened a unit — an empty history is an ordinary state — and the Dashboard then falls back to unit 1 of the **most-populated** level plus the newest podcasts — `StudyLevelController::index` now returns `units_count` (via `select(...)->withCount('units')`, not `get([...])`, which would drop the subselect) so the Dashboard can pick the level with the most content instead of whichever sorts first, and empty levels never surface in the tile. Its study tile is built from a **unit**, not a level (level cover + `Unit N` + level title + the unit's English title + its Chinese line), which needs a second call: `GET /study-levels` omits units, only `GET /study-levels/{id}` loads them, so the tile is chained after the list and fails soft. Unit titles are authored as `中文 - English` but **inconsistently spaced** (`接你们 - We` and `接你- We` both exist), so the split matches the first dash with optional surrounding space and only treats it as a split when the left half contains Han characters — an English title with a hyphen is left intact. Building any of these for real means a new tracking subsystem, not a new query. The chart **scales to the busiest day**, and the dashed rule marks that day — it sits on top of the tallest bar, labelled with that day's time. It used to mark the *average*, which on a real week (one busy day, six quiet ones) put it near the floor and read as a broken chart. The bars and the rule live in a shared `.db-plot` box: `.db-chart` carries the padding for the chip above and the weekday labels below, so if the rule positioned itself against that padded box its percentages would resolve against a different height than the bars' and it would miss the bar top by ~37px. Both ratios are computed from `seconds`, not the rounded `hours` field: at small totals the 2dp rounding is a large fraction of the value and would put the average line visibly off its true position. Do not floor the scale at one hour (an earlier version did): it pinned every bar to the bottom until a user had logged a full hour, which read as a broken chart with the average line stuck on the floor. Durations are labelled in minutes below an hour — "0.01 hours" carries no information on a real early week.
- **Top Reads' filter pills are `articles.type`** (All/Article/Story/Fun fact), not the mockup's Daily life/Technology/Travel/History, which correspond to no column.
- **Study is a three-level admin-authored hierarchy, not a flat list like Read/Podcast**: `study_levels` (e.g. "HSK 3") hasMany `study_units` (e.g. "Unit 1", also carries a `reading` text column) hasMany `study_vocabulary` (hanzi/pinyin/translation). Same `is_admin` gate as Read/Podcast at every write endpoint. Routes are nested under their parent (`POST /study-levels/{level}/units`, `POST /study-units/{unit}/vocabulary`) rather than flat, since — unlike Podcast/Article — the content only makes sense inside its parent. Frontend mirrors the hierarchy 1:1: `Study.jsx` (levels) → `StudyLevel.jsx` (`/study/:id`, units within a level) → `StudyUnit.jsx` (`/study/units/:id`, vocabulary + reading within a unit, `<Route>` order matters — `/study/units/:id` must be declared before the more generic `/study/:id` in `App.jsx` or the router matches the wrong one). `StudyUnitController::show` runs `DictionaryService::annotate()` on `reading` exactly like Read/Podcast, so `StudyUnit.jsx` reuses the identical hover+Alt+1 flashcard-save pattern (`source_module: 'study'`) — the update endpoint requires `title` on every save even when only editing `reading`, so the frontend always resends the unit's current title/description alongside the new reading text. `StudyUnit.jsx` renders `study_vocabulary` under a "New Words" heading directly below Reading (not a separate "Vocabulary" tab) — same data/endpoints, just positioned to match the mockup's reading-with-adjacent-word-list layout. Grammar (`study_grammar_points`: title/description/structure, one-to-many per unit via `Api\StudyGrammarPointController`, with examples as their own `study_grammar_examples` rows — chinese/pinyin/english/position, auto-pinyin via `DictionaryService::pinyinFor()` exactly like `StudyTextController`; the API returns them nested as `grammar_points[].examples`. The original flat `examples` text column was dropped by rebuilding the table in raw SQL, since this machine's SQLite 3.33 predates `ALTER TABLE DROP COLUMN` (3.35+) and doctrine/dbal — which Laravel's `dropColumn` needs on SQLite — isn't installed) and Culture (`study_units.culture_title`/`culture_body`, single note per unit, edited the same way as `reading` through `StudyUnitController::update`) are also done. Culture also carries a highlighted **term** (`culture_term` + `culture_term_pinyin`) and a **photo carousel** (`study_culture_images`: path/position, uploaded to the `public` disk with a `url` accessor exactly like `Article::image_url`, and the file is deleted from disk alongside the row). The term's reading comes from `DictionaryService::pinyinForTerm()`, which joins syllables with no separator (`nóngjiālè`) — distinct from `pinyinFor()`, which spaces them, right for a sentence and wrong for a single headword. Layout is measured off `design/study/culture.png`: a black card (radius 20) with the image + dot strip on the left and the title/term pills centred on the right, then a white body card inset only 4px from the card's sides leaving a 37px black band beneath it — that band is the design's signature, so don't "fix" it into even padding — note the API returns the grammar relation as `grammar_points` (snake_case, from `->toArray()`), not `grammarPoints`. All five content types are done. Quiz (`study_quiz_questions`: question/option_a-d/correct_option, via `Api\StudyQuizQuestionController`) is fixed 4-option multiple choice, chosen since the mockup showed it as an empty placeholder with no fields to build from. `correct_option` is hidden from every `GET` response (`$hidden` on the model — it's stripped even from the admin's own create response) so it can never leak through the network tab; a dedicated `POST /study-quiz/{question}/check` endpoint validates the submitted answer server-side and returns `{correct, correct_option}` only after the user has answered. The user is populating real HSK content themselves, so don't hardcode any curriculum content into the frontend.
- **All unit editing goes through one drawer too**: `StudyUnit.jsx` is read-only — one "Edit unit" button (`.un-edit`, in the section-label row) opens `components/StudyUnitEditDrawer.jsx` with a tab per content type, and it opens on whichever tab the page is already showing. This replaced 8 inline forms and 5 separate `editing*`/`show*` toggles; the page dropped from 1204 to ~500 lines and 25 orphaned `un-` rules came out of the stylesheet. A single `run(key, work, done)` wrapper inside the drawer owns the error reset, the busy flag and the flash, so eighteen mutations don't each restate them. **Answering a quiz question stays on the page** — that is student functionality, not editing. `StudyUnitController::update` returns the bare model with no relations loaded, which is why `{...unit, ...updated}` after a culture save does not wipe `vocabulary`/`texts`/`grammar_points`; don't add a `->load()` there without revisiting that. All four quiz options are `required` server-side — the old page form left C and D optional, which just produced a 422 on submit.
- **Podcast is Read's exact pattern with audio added**: `podcasts` table (`user_id`, `title`, `level`, `bio`, `audio_path`, `transcript`), admin-gated create/update/delete (`is_admin`, same as Read), `PodcastController::show` runs the same `DictionaryService::annotate()` used by Read for hover-translation over the transcript, and `PodcastEpisode.jsx` reuses the identical hover+Alt+1 save pattern (`source_module: 'podcast'`). Only real difference: a native `<audio controls>` element sourced from `audio_url` (appended accessor, same as `Article::image_url`), and audio upload validates via `mimes:mp3,wav,m4a,ogg,aac,flac,mp4` (extension-based) rather than `mimetypes` (content-sniffed) — PHP's fileinfo reports WAV as `audio/x-wav` not `audio/wav`, so content-sniffed mimetype validation rejected valid uploads. `level` is a fixed enum (`Beginner`/`Intermediate`/`Advanced`, validated server-side via `in:`) and `bio` is free-text — both nullable, shown on the list row and the episode header, no visual design applied (per functionality-first).
- New Eloquent `create()`/`updateOrCreate()` calls don't reflect DB-level column defaults on the returned model (SQLite doesn't round-trip them) — set defaults explicitly in the controller before `create()`, not just in the migration. Same root cause bit both `Flashcard.source_module` and `Booking.status`.
- Setting a foreign key that isn't in the target model's `$fillable` (e.g. `TutorProfile.user_id`) via a raw `Model::updateOrCreate(['user_id' => ...], $data)` silently drops it — mass assignment protection applies even to the match/attributes array. Always create through the owning relation instead (`$request->user()->tutorProfile()->updateOrCreate([], $data)`), which sets the FK directly and bypasses `$fillable` for that column only — same pattern already used for `flashcards()`/`scans()`.
- PHP 8.0 (this dev machine) does not support unpacking string-keyed arrays with `...$array` inside an array literal (that needs PHP 8.1+) — use `array_merge()` instead. Bit us once in `ArticleController::show`.
- `app/Exceptions/Handler::unauthenticated()` is overridden to always return a JSON 401 — the Laravel default falls back to `route('login')` when the request lacks an `Accept: application/json` header, which 500s here since this is an API-only app with no named `login` web route. The real frontend always sends that header so this never surfaced through the UI, only through bare `curl`/Postman calls. Don't remove the override.

CORS (`config/cors.php`) is locked to `http://localhost:5173`, `supports_credentials` is `false` since auth is token-based, not cookie-based.

**Rate limiting is split into two buckets** (`RouteServiceProvider::configureRateLimiting`): `api` is 300/min keyed by user id (or IP when logged out), and `auth` is 10/min keyed by IP and applied only to `POST /register` and `/login`. The general limit has to be generous because one page view fans out to several requests and React StrictMode doubles them in dev — the old shared 60/min tripped during ordinary browsing. Don't relax the `auth` bucket to match; it's the brute-force surface.

**A failed request must not end the session.** `api.js` attaches the HTTP status to every thrown error (`error.status`) and `AuthContext` clears the token *only* on a genuine 401. Before that, any failure — a 429, a 5xx, a network blip — hit the same catch-all and silently logged the user out, which looked like random logouts. A 429 also gets rewritten to a friendly "Too many requests. Please wait a moment and try again." instead of Laravel's raw "Too Many Attempts."

### Settings

`pages/Settings.jsx` (prefix `se-`) at `/settings`, linked from the sidebar **below the spacer** rather than in the Study Area list, since settings are not study content. Every control changes something real — there are no decorative toggles.

- **Account**: display name via `PUT /user/profile`. **Email is deliberately read-only** and the page says why: changing it needs a verification round-trip to prove the new address belongs to the user, and this app sends no mail — offering the change would let someone lock themselves out. `AuthContext` now exposes `setUser` so a rename updates the sidebar without a refetch.
- **Password**: `PUT /user/password` requires `current_password` even though the caller already holds a valid token — a token left on a shared machine is exactly the case this guards. On success every *other* token is revoked (the caller's own is spared, or you would be signed out of the tab you did it in).
- **Appearance**: the interface scale writes `--app-scale` (`src/appScale.js`, applied in `main.jsx` **before render** so the app never paints at the wrong size and then jumps). `--app-vh` is `calc(100vh / var(--app-scale))`, so the sidebar's height correction follows the scale automatically and needs no setting of its own — verified at 100/110/125%: the sidebar stays exactly viewport-height with zero phantom scroll at every step. `getAppScale()` only accepts values from `SCALE_OPTIONS`, so a hand-edited localStorage entry cannot render the app at 40x. The sidebar-collapse default writes the same `sb-collapsed` key the rail's own toggle uses.
- **Your data / sessions**: counts from `GET /user/stats`, and `POST /user/sessions/revoke-others` signs out every other device. It returns the count so the UI reports what actually happened rather than claiming success on a no-op.

### Read — admin-authored content with hover-translation

Modeled after the [Zhongwen popup dictionary](https://github.com/cschiller/zhongwen): admins publish articles/stories/fun facts (`articles` table: `title`, `type`, `body`, `body_en`, `image_path`, `user_id`), and any word in the body can be hovered for pinyin + English and saved to the flashcard bank with Alt+1 (`source_module: 'read'`).

- **Admin gating**: `users.is_admin` boolean (default false). No signup UI for it — promote an account manually via `php artisan tinker` (`User::where('email', '...')->update(['is_admin' => true])`). Enforced both server-side (`abort_unless($request->user()->is_admin, 403)` in `store`/`update`/`destroy`) and client-side (`{user?.is_admin && ...}` hides the create/edit/delete UI) — the server check is the real gate, the client one is just UX.
- **Hover-translation data comes from the same CEDICT index Scan already built** — no new dictionary or API. `DictionaryService::annotate()` (separate from `segment()`, used by Scan) tokenizes the *entire* body text, not just the Chinese words: Han-character runs become `{type: 'word', text, pinyin, translation}` tokens via longest-match against the index, everything else (whitespace, punctuation, English) passes through untouched as `{type: 'text', text}` tokens so the frontend can reproduce the original formatting exactly (rendered inside a `white-space: pre-wrap` block). `ArticleController::show` is the only place this runs — `index` returns lightweight rows without `body`/`tokens`, but it *does* fetch `body` internally to derive a 120-char `excerpt` for the card previews and then `unset()`s it before returning, so list payloads stay small while cards still have description text.
- **`body_en` powers the EN/CN toggle on the reader** (`articles.body_en`, nullable text). Chinese-only articles stay valid: when it's empty the EN button renders `disabled` with a "No English translation for this article yet" tooltip rather than showing a blank pane. CN is the default since the Chinese text is the actual learning content — it renders the annotated tokens with hover+Alt+1, while EN renders plain `body_en` with no tokenization. Both the create form (`Read.jsx`) and edit form (`ReadArticle.jsx`) expose it as an optional textarea.
- **Images**: uploaded to the `public` disk (`storage/app/public/articles/`), served via `php artisan storage:link` (already run — `backend/public/storage` is a symlink) and `Article::image_url` (an appended accessor, not a raw column). Editing with a new image deletes the old file first.
- **`APP_URL` must match the actual `php artisan serve` address** (`http://127.0.0.1:8000`, not the Laravel default `http://localhost`) — `Storage::disk('public')->url()` builds absolute URLs from it, and a mismatch means article images 404/connection-refused in the browser even though the API calls themselves work fine. Already fixed in `.env`/`.env.example`; don't reintroduce the default.
- Update uses `PUT /articles/{article}` with Laravel's `_method` form-spoofing field, since browsers can't send a real `multipart/form-data` PUT — the frontend (`api.updateArticle`) appends `_method=PUT` to the `FormData` and POSTs.

### Find Tutor — self-service two-sided marketplace

Any user can become a tutor by filling out their own profile; no admin approval step, unlike Read's `is_admin` gate.

- **Tutor profiles**: `tutor_profiles` table, one row per user (`user_id` unique FK), `bio`/`subjects`/`hourly_rate`/`languages_spoken`/`availability`/`photo_path` all nullable. `TutorController::store` is an upsert (`updateOrCreate`) keyed on the authenticated user, so the same endpoint creates the profile the first time and edits it after — the frontend's button label just switches between "Create tutor profile" and "Update profile" based on whether `GET /tutor-profile` returned a profile. Photo upload follows the exact same pattern as `Article::image_path`/`image_url` (public disk, `photo_url` appended accessor, old file deleted on replace).
- **Styled areas so far: the sidebar shell, Dashboard, Find Tutor, Scan, Read (list + article), Login and Register.** Each has its own stylesheet with a unique class prefix — `Layout.css`/`sb-`, `Dashboard.css`/`db-`, `FindTutor.css`/`ft-`, `Scan.css`/`sc-`, `ScanDocument.css`/`sd-`, `Read.css`/`rd-` (shared by `Read.jsx` and `ReadArticle.jsx`), `Login.css`/`lg-`, `Register.css`/`su-`. The Podcast/Reads switch is the shared `components/SectionToggle.jsx` (prefix `tg-`, self-contained colours) used by `Read`, `ReadArticle` and `Podcast` — it was previously duplicated markup against near-identical `.rd-toggle` and `.pc-toggle` rules, which is exactly how the two pages silently drifted apart (different fill, gap and indicator depending on which page you were on). Its active indicator is an absolutely-positioned `::after` on the label rather than `text-decoration: underline`, because that property cannot take rounded caps and cannot be excluded from the icon; the pill's uneven vertical padding (6.6/12.6) is derived from the indicator's 6px overhang, not eyeballed. Separate files, not shared, but the same token values so they stay consistent. **Edit drawers share `components/EditDrawer.jsx` + `EditDrawer.css` (prefix `ed-`)** — the scrim, sliding panel, header, tab strip and scrolling body, plus the field/list/button primitives the tab bodies use. `TutorEditDrawer` and `StudyUnitEditDrawer` supply only their tab contents. Extracted for the same reason as `SectionToggle`: two near-identical drawers against two near-identical stylesheets is exactly how things silently drift apart. Everything else (Flashcards, Podcast, Study, Practice) is still deliberately unstyled per the functionality-first approach. Built from user-supplied Figma exports (purple/lavender palette: `#6c4fd1` accent, `#f6f5fc` light background, `#2b2643` dark navy), not a generic default.
- **Fonts are self-hosted, not Google Fonts** — `frontend/src/fonts.css` (imported from `main.jsx`) declares Hellix (400/500/600/700, licensed `.woff2` from `font/` at the repo root) and Douyin Sans. Sora/Inter were removed. **Douyin Sans ships only weight 700** — it is bold-only, so using it anywhere forces the text bold no matter what `font-weight` says; keep it for display headings (Dashboard greeting/quote) and keep it *out* of body copy. **Hellix has no CJK glyphs** (verified by measurement: Chinese in `Hellix, cursive` renders identical to `cursive` alone). Always list Hellix first so Latin/digits/punctuation use it, then let Chinese fall through — to Douyin Sans for display, or to `PingFang SC`/`Microsoft YaHei`/`Noto Sans SC` for regular-weight reading text.
- **Never use raw `100vh` inside `#root` — use `var(--app-vh)`.** `#root` carries `zoom: var(--app-scale)` (1.1) for the global 110% scale, and **`vh` is not affected by zoom**: `100vh` still resolves to the full viewport in CSS px and is then scaled up, so a `100vh` box renders 10% taller than the screen. That gave every page ~10% of the viewport in phantom scroll, and — because the sidebar is `position: sticky` — made it taller than its own scrollport, which a sticky element cannot stay pinned inside: it slid up by 72px as you scrolled. `--app-vh: calc(100vh / var(--app-scale))` (both defined on `:root` in `fonts.css`) is the corrected unit; all 16 former `100vh` declarations now use it.
- **`html { overflow-y: scroll }` is deliberate.** Short pages (Practice, Flashcards) do not overflow, so without it the scrollbar appears and disappears between pages and shunts the whole layout 15px sideways. `scrollbar-gutter: stable` does **not** work here — it only applies to scroll containers and the root element's overflow propagates to the viewport, so Chrome computes `stable` on `<html>` but reserves nothing (verified: `/practice` measured 1280 while every other page measured 1265).
- **Never set `min-height: 100%` on a page container inside `.sb-main`.** It resolves against an auto-height parent and pushes content past the flex wrapper (was 64px of phantom scroll), which also breaks the sticky sidebar. `.sb-main` already carries `min-height: 100vh`; if a page needs its own background to fill the viewport use `min-height: 100vh` *plus* `box-sizing: border-box` on the page container, and re-check that `document.scrollHeight === .sb-shell` height afterwards.
- Real design assets live in `design/` at the repo root (Figma exports: `Dashboard.jpg`, `Sidebar.png`, `banner/`, `icon/`) — reference-only, not committed into the frontend build; individual assets actually used get copied into `frontend/src/assets/` (e.g. `design/banner/学.png` → `frontend/src/assets/dashboard/hanzi-decoration.png`; the 6 sidebar icon PNGs and the cropped logo badge → `frontend/src/assets/sidebar/`). Every exported PNG icon/decoration is white-on-transparent (confirmed via canvas/Pillow pixel sampling before use, since they render invisible in a plain image preview against a white background) — never apply a CSS invert filter to them, they're already white and show correctly once placed over the dark sidebar/purple banner. **All 8 sidebar nav icons are now inline SVG in `Layout.jsx`** (a shared `NavIcon` wrapper, 24px grid, `strokeWidth 1.7`, `stroke="currentColor"`, rendered 19px) — the Figma PNG exports were 1× rasters that looked soft on high-DPI screens and, being baked white, could never respond to hover/active colour. The old `icon-*.png` files are still on disk but unused. **The sidebar collapses to a 76px icon rail** — a toggle in its header sets `.sb.collapsed`, and the choice is persisted to `localStorage` under `sb-collapsed` (read lazily in `useState` so the first paint is already correct and the rail never flashes open). Collapsed hides the labels, section heading, user name and promo card; nav links keep a `title` so the tooltip carries the name the hidden label used to, and the logout button keeps an sr-only label behind its glyph. The expanded sidebar (and the Login/Register panels) use `assets/sidebar/logo.png` as an `<img>`. It is a **1x 176x42 export**, so it softens once anything scales it — the app's `zoom: 1.1` alone does, before any HiDPI ratio. Rebuilding it as markup (CSS pill + live Hellix text) was tried and reverted at the user's request; if the softness comes up again, the fix is a 2x/SVG export from Figma rather than another rebuild. That pill cannot be cropped to a mark without slicing its rounded edge, so the chevron mark was **extracted to its own transparent PNG** (`assets/sidebar/logo-mark.png`, 40x27) and the rail shows that. It was un-blended rather than plain-cropped: each pixel's alpha comes from its distance from the pill background `#4f486f` and the colour is recovered by removing the background's contribution, so the antialiased edges stay smooth instead of picking up a hard purple matte. `.sb` needs `overflow-x: hidden` and `white-space: nowrap` on its rows: `display` cannot transition, so labels appear the instant the class flips while the width is still animating, and the existing `overflow-y` would otherwise compute `overflow-x` to `auto` and flash a scrollbar mid-transition. The sidebar itself is `position: sticky; top: 0; height: var(--app-vh)` with internal overflow, and the active item is a `--sb-card` pill plus a 4px `--sb-accent` bar drawn with `.sb-nav-link.active::before`.
- **List → detail is the same pattern as Read**: `FindTutor.jsx` (list, `GET /tutors`) links each card to `TutorProfileDetail.jsx` (`/find-tutor/:id`, `GET /tutors/{tutorProfile}`) via `TutorController::showProfile`. The detail page independently fetches bookings to check whether the current user already messaged this tutor (`bookings.sent.some(b => tutor_id matches)`), since that state isn't passed through navigation.
- **All tutor editing goes through one drawer**: the detail page has a single "Edit profile" button (`.td-edit`, in the profile card header) that opens `components/TutorEditDrawer.jsx`, built on the shared `components/EditDrawer.jsx` shell (prefix `ed-`) — tabs for **Profile** (bio/subjects/languages/availability/rate/photo/intro video), **Resume** and **Lessons**. Each tab **saves against its own endpoint at its own moment**; there is deliberately no single drawer-wide Save, because the profile is one upsert while lessons and resume entries are collections with add/delete, and a batched save could not report a partial failure honestly. The drawer takes an `onChange` callback and hands the updated profile back, so the page behind it stays in step without a refetch. Everything is read-only on the page itself — no inline add/delete buttons — so there is exactly one place to edit.
- **`TutorController::authorizeProfile()` is the one authorization rule** for a profile and everything hanging off it: the owning tutor, **or an admin acting on their behalf**. It's a static method the lesson and resume controllers both call rather than each restating the check. The admin path is not a convenience — the seeded tutors' accounts have no usable password, so without it their profiles would be uneditable by anyone. This is why the write routes are profile-scoped (`POST /tutors/{tutorProfile}/profile|lessons|resume`) rather than hung off `/tutor-profile`: the older self-only form is an upsert keyed on the authenticated user and can only ever reach the caller's own row. `POST /tutor-profile` still exists as the "Become a tutor" create path on `FindTutor.jsx`.
- **Lessons are owned by the tutor profile, not the user directly**: `tutor_lessons` table (`tutor_profile_id`, `name`, `description`, `price`), via `TutorLessonController` (`POST /tutors/{tutorProfile}/lessons`, `DELETE /tutor-lessons/{lesson}`).
- **Resume is real data, not the mockup's placeholder**: `tutor_resume_entries` (`tutor_profile_id`, `section`, `years`, `title`, `detail`, `position`) via `TutorResumeEntryController`. `section` is validated `in:` against `TutorResumeEntry::SECTIONS` (`Education`/`Certifications`) — a plain string column rather than an enum, since this machine's SQLite has no usable `ALTER` for changing one later. `years` is free text ("2016 — 2017", "2018") rather than two date columns, because resume dates are routinely year-only or open-ended and the design shows the range as written. The tab strip on the page is the fixed `RESUME_SECTIONS` constant so it stays stable when a section is empty. The mockup's **"Diploma verified" note was dropped** — these entries are self-entered, so the badge would assert a verification nothing performs. Stats (rating/students/lessons/experience) and reviews are still `PLACEHOLDER_*` constants with no backend.
- The drawer's slide-in animation is a 24px nudge plus a fade, **not** `translateX(100%)`. A CSS animation only advances while the tab receives frames; a keyframe starting the panel a full width off-screen strands it there, unreachable, if those frames never arrive (observed in a backgrounded tab). Starting 24px out caps the worst case at a panel slightly off its mark but fully usable.
- **Bookings are a simple request record, not a scheduler**: `bookings` table (`student_id`, `tutor_id`, `message`, `status` default `pending`) — no date/time slots, no accept/reject action yet, just a contact request a student sends a tutor. `BookingController::index` returns both directions in one call, `{sent, received}`, since any user can be both a student and a tutor simultaneously.
- A user cannot book themselves — enforced server-side in `BookingController::store` (`tutor_id === $request->user()->id` check), not just hidden client-side.
- Same string/int FK gotcha as elsewhere: `tutor_profiles.user_id` and `bookings.student_id`/`tutor_id` come back as strings from SQLite on list endpoints, so the frontend coerces with `Number(...)` before comparing against `user.id` (e.g. to detect "this is your own profile" or dedupe your profile out of a stale list).

### Scan (OCR) — environment dependencies

Scan shells out to a local Tesseract binary rather than a paid cloud OCR API. This means the feature depends on machine state that isn't part of the repo:
- **Tesseract OCR** must be installed system-wide (`winget install UB-Mannheim.TesseractOCR`). Path is configurable via `TESSERACT_PATH` in `.env` (defaults to `C:/Program Files/Tesseract-OCR/tesseract.exe` — forward slashes, since Laravel's dotenv parser treats backslashes in double-quoted values as escape sequences).
- **`chi_sim.traineddata`** (Simplified Chinese language data) is not bundled with the Tesseract installer and isn't writable into `Program Files` without admin rights, so it lives project-locally at `backend/storage/tessdata/` instead (fetched from `tessdata_fast` on GitHub) and is passed to Tesseract via `--tessdata-dir` in `OcrService`.
- **CC-CEDICT** (`backend/storage/dict/cedict_ts.u8`, from mdbg.net) is the offline English translation source — no translation API is used. `DictionaryService` parses it into a simplified-word → definition index, cached to `backend/storage/dict/cedict_index.php` (regenerated automatically if deleted). Chinese text has no spaces, so `DictionaryService::segment()` does greedy longest-match word segmentation against this same index before translation/pinyin lookup.
- Pinyin (with tone marks, not numbers) comes from the `overtrue/pinyin` composer package, applied per-segmented-word — not from CEDICT's own numeric-tone pinyin field.
- None of `storage/tessdata/*.traineddata`, `storage/dict/*.u8`, or `storage/dict/*_index.php` are committed (see `backend/.gitignore`) — they're large, machine-fetched assets. A fresh checkout needs Tesseract installed and both files re-downloaded before Scan works.

Supabase (DB/auth) is planned but not yet integrated — no credentials or config exist in this repo. Deployment target is Vercel.

**Known constraint:** the dev machine runs PHP 8.0, which caps Composer to Laravel 9 (EOL). Laravel 10 needs PHP 8.1+, Laravel 11 needs PHP 8.2+. Upgrade PHP before upgrading Laravel major versions.
